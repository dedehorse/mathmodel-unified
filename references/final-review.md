# 论文与交付终审

只在论文终审、提交前检查或完整流程收尾时读取。先明确审查对象和版本。赛事合规依赖比赛名称、年份、赛区和官方依据。通用技术与排版核查可先完成。

| 请求 | 核查范围 |
| --- | --- |
| 技术验收 | 核对题意、模型、代码、数据、图表和结论能否互相印证。 |
| 格式合规 | 核对指定模板、排版、匿名和当届规则。仅查格式时按请求范围出报告。 |
| 按题评分 | 核对各问完成度及评分依据。区分官方评分细则与自行拟定的参考分，不将参考分当成获奖预测。 |
| 提交前终审 | 综合核对适用项目并复用同一稿件版本的检查记录，补查未覆盖项。 |

| 类别 | 核查问题 | 证据 |
| --- | --- | --- |
| 题意与模型 | 顶层问题是否全答；假设、变量、约束与实际求解是否一致 | 题面、分析报告、代码 |
| 数值 | 摘要、正文、图表、附录和结果文件是否同口径；关键结论能否复算 | 原始数据、日志、结果表 |
| 图表 | 是否来自真实数据或真实方法；标题、单位、图例、正文引用是否一致 | 图表源文件与 PDF |
| 文献 | 是否真实、确实使用且引用位置正确 | DOI、出版社或原始文献记录 |
| PDF | 是否可搜索、图文清晰、章节完整、表格不越界、无占位符 | 最终版 PDF 与编译日志 |
| 身份与合规 | 是否泄露姓名、学校、账号、文件元数据等赛事禁止的信息 | 官方规则、PDF 属性、附件 |
| AI 使用 | 使用声明与详情、允许范围、人工核验记录是否符合当届规定 | 官方规则与团队记录 |
| 提交 | 文件名、摘要/正文/附录、支撑材料、校验值或提交窗口是否符合规定 | 当届官方提交说明 |

技术验收由 `6verity` 或已有项目的技术检查负责，通用格式审查可调用 `bzd-paper-format-checker`，按题打分才调用 `bzd-review-paper`。CUMCM 专项终审可调用 `cumcm-live-workflow`。引用同一稿件版本的既有报告并补缺项；提交前将此次修改及依赖项复核。可直接修复的错误按用户授权处理；缺少依据的条目标记“待核实”。不要将参赛论文上传到未获授权的查重或 AI 检测站点。
